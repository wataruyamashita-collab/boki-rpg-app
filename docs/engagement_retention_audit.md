# 簿記3級学習システム：面白さ・探求心・継続性・飽きにくさ総合監査

監査日: 2026-08-24  
対象: 現在のリポジトリ実装（仕様書より実装を優先）  
方法: HTML/CSS/JavaScript、300問の全データ、状態保存・採点・RPG・復習・模試ロジック、テストを静的監査し、問題分布・重複をスクリプト集計した。以下の継続人数は実測ではなく、年齢、学習目的、ゲーム嗜好、端末、可処分時間、既習度を分散させた100人の仮想受講者によるUX仮説である。

## 1. エグゼクティブサマリー

**結論: 最初の数問は「問題集より面白い」が、現状のまま30日使って「簿記そのものが面白い」へ移る設計には達していない。**

1. 現状は **TYPE 1.8（ゲーミフィケーション付き問題集寄り）**。会社員の役割、章、取引額、HPは簿記の語彙を使うが、理解の深まりがゲーム世界を変えるところまでは融合していない。
2. 入口は明快で、初回から「続きから」で1問へ入れる。仕訳は5択、金額入力、確信度選択という短いループで、スマートフォンのタップ領域も配慮されている。
3. 150仕訳＋150表問題、7 type、12章、4モードは量的には強い。仕訳の誤答診断、正しい仕訳、根拠の説明は初学者の有能感を支える。
4. 一方で、**非仕訳問題が参照する `materials` をViewが一切描画しない**。訂正20問・総合10問などは必要な証憑・取引資料が見えず、正答不能または意味不明になる。公開前P0である。
5. 表問題の結果画面はセル別正答・本人回答・正答表を表示しない。部分点を内部計算しても学習者には「正解／もう一歩」しか見えず、誤概念を修正しにくい。
6. XPは初回正解にしか付かず、分野別習熟度は保存されるが画面に出ない。レベルアップ通知、次レベルまでの残量、解放、称号、コンボ、ストリークは未実装である。
7. HPは誤答に罰を与え、0で資金ショートにする。初心者ほど失敗する学習初期に損失を強調し、しかも「勝負回答」は正解XP 3倍／誤答HP -30で、理解より賭け判断を前景化する。
8. 復習は「最後に不正解だった問題」の単純集合で、正解すると即時除外される。間隔反復、忘却予測、論点別弱点、再定着確認はない。
9. 問題データの構造整合性と仕訳貸借一致はバリデータで守られ、代表問題の計算も整合する。ただし大量の同文・数値差し替え型反復があり、30日では答え・型の記憶が理解を代替しやすい。
10. ストーリーは職場文脈を与えるが、選択、対話、葛藤、結果分岐はない。同じ月・同じ先輩の導入文がまとまって繰り返され、「続き」より問題番号の連続に近い。
11. 100人仮説では初日終了72人、3日後44人、7日後27人、14日後17人、30日後9人。ゲーム好き・短時間反復層には刺さるが、概念理解層、ゲーム嫌い、失敗不安の強い初心者には刺さりにくい。
12. 最大の改善レバーは機能の足し算ではなく、**「資料→判断→仕訳/集計→会社への意味→次の問い」を一問内で閉じる理解フィードバック**である。まず表示欠陥を直し、その後に知識連鎖と適応復習へ進むべきである。

## 2. 現在のユーザー体験

### 実装から再構築したジャーニー

1. **初回アクセス**: ヘッダー直下にLv.1・経理見習い・EXP 0・HP 100・総取引処理額0円が出る。ストーリー、トレーニング、復習、模試の4タブと検索フィルターが同時に見える（`index.html:17-40`, `js/view.js:updateRpg`）。オンボーディングや事前診断はない。
2. **学習開始**: 初期表示はストーリー。「次の仕事」とChapter進捗0/nを示す「続きから」が主要CTA。任意問題選択も可能で自律性はある（`js/controller.js:renderModes`）。
3. **問題を見る**: ストーリーモードでは章・scene・同章共通のstory・取引文を表示。仕訳以外では表を表示するが `materials` は表示しない（`js/view.js:renderQuestion`, `renderTable`）。
4. **回答する**: 仕訳は正答行数と同数の行、正答科目を含む最大5択、金額欄。表は指定セルへ金額/文字列を直接入力。内蔵計算機、入力自動保存、慎重/勝負回答がある。
5. **正誤判定**: 仕訳は貸借合計一致かつ科目・金額の多重集合完全一致。表はセル単位の完全一致で部分点を計算する（`js/engine.js:gradeJournalEntry`, `gradeTable`）。
6. **フィードバック**: 仕訳誤答は本人仕訳、正しい仕訳、貸借逆・科目・金額・未入力の診断、解説を表示する。表問題は正答表もセル診断もなく、本文解説だけである（`js/view.js:result`〜`renderCorrectJournal`）。
7. **次問**: 結果末尾の「次へ進む」で現在モードの配列上の次IDへ進む。次問予告、残りXP、連続正解、セッション目標はない。
8. **成長変化**: 非模試で正解すると、その問題の初回のみ `20 × difficulty × ratio × 確信度倍率` XPを付与。Lvは平方根式で1〜30、役職はLv5/10/20/30で変わる。HPは正解+5、誤答-10/-30。習熟度は保存するが非表示（`js/rpg.js`）。
9. **終了**: 明示的なセッション終了、今日のまとめ、称賛、次回提案はない。最後の問題後はモード一覧へ戻る。HP 0なら資金ショートダイアログが割り込む。
10. **翌日再訪**: localStorageからモード、現在問題、回答済み、誤答、下書き、XP等を復元し、「最初の未回答仕訳」を続きとして出す。日付、学習日数、前回要約、リマインドはない。
11. **数週継続**: 問題は固定順。模試だけ受験回数を起点にtype別プールを巡回するがランダムではない。新体験の解放はない。
12. **復習**: 直近回答が誤答のIDを一覧化し、正解すると即座に対象外。累積誤答回数順の絞り込みは可能だが、期日・間隔・再失敗履歴・習熟判定はない（`js/model.js:record`, `js/controller.js:filteredIds`）。
13. **成長実感**: Chapter回答数、Lv/役職、EXP、HP、総処理額、各問題の誤答回数は見える。正答率推移、分野別習熟、昨日比較、合格到達度は見えない。
14. **合格レベル接近**: 模試終了時に得点率と70%以上の「合格圏」を表示する。ただし15問の固定quota、時間制限なし、配点・出題構成は本試験再現ではなく、模試個票も保存しない。

## 3. 面白さ評価

### A-1 最初の5分

- **刺さる点**: 「経理シミュレーションRPG」「次の仕事」「経営HP」という再文脈化、即時開始、5択仕訳により、紙の問題集より着手障壁は低い。
- **弱い点**: 初画面に4モードと3フィルター、Lv/EXP/HP/総取引額が一度に現れ、各数値の意味や推奨ルートは説明されない。最初の取引は追加出資で、驚きや意思決定より教科書的仕訳である。
- **判定**: 初回5分は「少し面白そう／使いやすそう」までは届くが、「先が気になる」は弱い。ゲーム好き・資格目的には中程度、物語期待層には期待外れになりやすい。

### A-2 1問ごとの気持ちよさ

- 正解時は緑の「正解です！」、EXP/HP/総処理額更新、丁寧な根拠がある。誤答時も「もう一歩です」という非断罪表現と具体診断は良い。
- ただし音、アニメーション、レベルアップ固有演出、XP獲得量の差分表示はなく、毎回の結果はほぼ同型。既正解問題を再度解いてもXPも習熟も増えず、その説明もない。
- 仕訳は理解の喜びが生まれ得るが、表問題では自分のどのセルが正しかったか見えず、納得より答え合わせ不足が残る。

### A-3 成長実感

Chapterの `x / n` と役職は長期の量的進捗を示す。一方、回答済みは正誤に関係なく進捗へ数えられ、保存済み `mastery` は表示されず、昨日比較もない。ゆえに「進んだ」は見えるが「できるようになった」は弱い。

### A-4 小さな驚き

存在するのはレベル/役職閾値とHP 0イベント、問題形式が章後半で変わること。コンボ、称号、特殊イベント、フィードバック差分、新要素解放、ランダム教育報酬は確認できない。役職変化も専用通知がなくヘッダー文字が変わるだけで、見逃しやすい。

### A-5 学習との融合

「取引処理額」「経理役職」「資金ショート」は表層語彙として融合する。しかし処理額は正答データの金額合計で、学習上の難しさや会社成果とは無関係。HPは理解の質でなく単発正誤、レベルは累積XPだけである。簿記概念を組み合わせたことで会社の状況が読める、という因果はC問題の教材内容にはあるがゲーム状態には接続しない。

## 4. 簿記への探求心評価

### B-1 Why

J001等の解説は「現金は資産の増加、資本金は純資産の増加」のように理由を述べ、単なる正答列挙より良い。誤答診断も「何が増減したか→勘定科目」の思考手順へ戻す。反面、多くの表問題は計算結果と短い規則に留まり、ユーザーに仮説を立てさせる問い返しはない。

### B-2 知識の接続

章順とカテゴリは基礎仕訳→元帳→試算表→訂正→決算→財務諸表→総合へ進み、カリキュラム上の接続は存在する。しかしUIは前提論点、関連問題、概念マップを示さず、各問題は独立カードである。`learningRole` と `variantGroup` はデータにあるが選定・表示に使われないため、core→drill→transferという意図は学習者から見えない。

### B-3 新しい疑問

ストーリー本文は状況説明で、結果画面に「次は回収できなかった場合を考える」等の知的クリフハンガーがない。固定順に関連論点が後続しても、なぜ次に学ぶのかを言語化しない。知的連鎖はデータ配列に潜在するが体験として未成立である。

### B-4 解説品質

- **強い**: 仕訳の処理根拠、貸借合計、試験ポイントを構造化でき、科目に資産/負債等のバッジを付ける。J001は理由と貸借額が整合する。
- **中程度**: L001〜等は計算過程を示し、T001は「貸借一致でも記帳漏れ等を保証しない」と誤解まで予防する。
- **弱い**: 類似概念比較、実務上の証憑、次論点への橋渡しは一貫しない。「TAC講師の解説」という見出しは実装上の出典・監修証跡を確認できず、権威表示として不適切な可能性がある。
- **致命的**: 非仕訳の正答セル比較がない。解説文に答えがあっても、多セル問題で各入力の正誤を復元しにくい。

### B-5 答え暗記化

300問という総数だけなら豊富だが、仕訳150問は各カテゴリ原則3問、試算表は10問単位で同一問題文、訂正20問・財務諸表10問・総合10問はそれぞれ同一問題文である。元帳も同型文・同型表の数値差し替えが多い。固定ID順、選択肢配置もquestion IDから決まるため、30日には「この見た目ならこの操作」という項目記憶が強くなる。金額や条件が変わる一部の転移設計は評価できるが、理由説明・誤り発見・比較など生成的検索が少ない。

## 5. 心理学的継続性評価

| 理論 | 実装上の事実 | 心理作用と判定 |
|---|---|---|
| Self-Determination: Autonomy | 4モード、検索、問題選択、慎重/勝負 | 学習経路の自由はある。ただし初心者向け推奨経路がなく、確信度は賭け倍率なので質の高い自律性は中程度。 |
| Competence | 即時正誤、仕訳診断、章進捗、レベル | 仕訳では有能感を支える。表の不透明な誤答、HP罰、習熟非表示が相殺する。 |
| Relatedness | 水野先輩がstory/説明に登場 | 人物は反応も関係変化もせず、社会的つながりはほぼ成立しない。 |
| Flow | difficulty 1/2/3はデータのみ。選定は固定順 | 能力推定にも出題調整にも使わず、初心者は後半で難化、既習者は前半で退屈。Adaptive Difficultyは必要。 |
| Goal Gradient | Chapter x/n、Lv | 章ゴールは見えるが結果画面に残り問数/残りXPがなく、レベル報酬も弱い。部分成立。 |
| Zeigarnik | 「次の仕事」を表示 | ホームでは未完了感があるが、回答直後に次問の意味的予告がない。弱い。 |
| Variable Reward | HP/XP式は固定、問題順も固定 | 教育的に安全だが驚きはない。賭け倍率は変動報酬ではなく自己選択のリスクで、学習価値が薄い。 |
| Endowed Progress | 初期は0/n、EXP 0 | 先取り進捗はなく不成立。ただし最初の5択が易しく成功体験を作る可能性はある。 |
| Loss Aversion | HP減少、HP 0で資金ショート | ストリークより破壊的ではないが、誤答を学習資源でなく会社損失にする。数学不安層に離脱圧力。 |
| Peak-End | 明示的セッション終了なし | 最後の体験が誤答や資金ショートになり得る。今日の成果要約がなく不成立。 |
| Habit Loop | 再訪時「続きから」 | Routineと即時Rewardはあるが、日次Cue、時間目標、復帰メッセージがなく自発習慣には弱い。 |
| Cognitive Load | 44px操作、内蔵計算機、科目5択 | 仕訳入力負荷は抑える。一方4列をiPhone幅へ押し込み、長い科目名は11pxまで縮み、確信度/HP判断が本題へ外在負荷を加える。表は横スクロールが必要。 |

## 6. 飽きにくさ評価

### D-1 反復感

- **10問**: 取引文と科目が変わり、初学者には適度な反復。ゲーム枠も新鮮。
- **50問**: ほぼ同じ「文を読む→科目選択→金額→確定→同型結果」。物語も同章で同文が続き始める。
- **100問**: variantの数値・文脈差より操作形式の同一性が勝り、固定答えの再認が増える。
- **300問**: 後半に表形式は増えるが、同型10〜20問のブロックが続く。内容量はあるが体験多様性は不足。

### D-2 実装済み/未実装の形式

| 形式 | 状態 | 根拠・注意 |
|---|---|---|
| 通常/複合仕訳 | 実装 | journal 150問。正答行数が先に露出する。 |
| 勘定科目選択 | 実装 | 仕訳の各側最大5択。 |
| 金額計算 | 実装 | 全type。内蔵計算機あり。 |
| 元帳穴埋め | 実装 | ledger 50問。 |
| 試算表/訂正/精算表/財務諸表/総合 | データ実装 | 各40/20/20/10/10問。ただし資料非表示で一部体験不能。 |
| 誤り発見 | 部分実装 | correction 20問だが証憑 `materials` が見えず現状は成立しない。 |
| ケーススタディ | 部分実装 | comprehensive 10問だが複数資料が見えない。 |
| 逆仕訳 | 明示形式なし | 訂正で近い思考はあるが独立形式ではない。 |
| 比較問題 | 未実装 | 類似概念の選択理由比較はない。 |
| 理由説明 | 未実装 | ユーザーが理由を生成・選択して採点される問題はない。 |
| ストーリー分岐 | 未実装 | storyは固定背景で選択や結果反映なし。 |

### D-3〜D-6 マンネリ

- 演出は毎回、緑/赤の結果箱＋解説＋次へ。CSSのactive押下以外、アニメーションは確認できない。
- レベルは数字と5段階役職だけ変化し、入力方式・教材・会社状態・登場人物反応は変わらない。
- XP、総処理額、役職は用途がなく、数日で交換価値も情報価値も失う。HPだけは失敗時の強い意味を持つため、報酬より罰が目立つ。
- 学習順は体系的だが、各type/variantGroupの連続ブロックが長い。ランダム過多の問題はない一方、交互練習もない。

## 7. 問題・解説品質評価

### 全件構造監査

- **300問**: journal 150、ledger 50、trial_balance 40、correction 20、worksheet 20、financial_statement 10、comprehensive 10。
- **難易度**: 1が75、2が115、3が110。ただしdifficultyはXP計算に使うだけで、表示・適応出題には使わない。
- **章**: 12章。第8章に94問が集中し、章進捗94問はGoal Gradientを弱める。
- データ内validatorはID、必須field、仕訳貸借一致、入力セル、type件数、timeline、精算表注意、B/S限定条件、C資料重複を検査する。これは構造品質の強みだが、UI可視性や日本語・教育妥当性を保証しない。

### 内容サンプル監査

| ID群 | 評価 |
|---|---|
| J001 | 現金3,000,000/資本金3,000,000で貸借・説明とも正しい。資産増/純資産増の理由が初学者向け。 |
| J002/J003 | 資産内部振替を短く明示し、問題は一意。 |
| L001 | 305,000+53,000-26,500=331,500で正答・説明が一致。逐次残高の練習として成立。 |
| T001 | 借方410+175+60+289+90=1,024千円、貸方134+400+490=1,024千円。計算一致し、貸借一致の限界も説明。 |
| E001 | データ上は記録済み仕訳と広告領収書から（借）広告宣伝費/（貸）備品22,500が一意。しかしUIが `materials` を表示せず、問題文だけでは何を訂正するか不明。 |
| F001〜F010 | 「表に示した項目以外なし」の限定で差額計算の一意性を担保している。 |

### 品質差・コピー傾向

完全同一問題文はE001〜E020（20問）、Tの各10問群、F001〜F010、C001〜C010などに存在する。資料差分が教育的なら同文自体は誤りではないが、画面で資料が欠落するため差分が消え、文字通り同じ問題に見える。仕訳解説は構造化が比較的厚く、非仕訳は1段落中心で品質差がある。全300問について専門団体の監修証跡はリポジトリ内で確認できないため、日商簿記3級範囲・最新出題区分への完全適合は「確認できない」。

## 8. ゲーミフィケーション評価

### 存在するもの

- XP、Lv1〜30、5役職、会社HP、総取引処理額、確信度リスク、資金ショート、章進捗、固定ストーリー文脈。

### 存在しない/画面上確認不能なもの

### 評価

報酬の中心が「数字を増やす」だけで、簿記を理解すると企業の意思決定が改善する、帳簿が完成する、説明できる範囲が増える、といった意味的報酬がない。確信度設計はメタ認知を促し得る着想だが、現状は正答後の確信度較正を記録せず、XP 3倍/HP -30という賭けへ変換している。ゲームとしても戦略が薄く、教育としても推測回答を促す懸念がある。

## 9. 「ゲームの面白さ」と「簿記の面白さ」の分離評価

**現状: TYPE 1.8 / 3.0。**

- TYPE 1より良い理由: 会社の取引を仕訳し、元帳、試算表、財務諸表へ進む内容順そのものは経理の仕事に沿う。C問題の「現金≠利益」など、本質的発見の素材もある。
- TYPE 2未満の理由: ゲーム状態は簿記理解の構造を表さない。現金取引を誤ってもHPが減るだけで、帳簿や会社判断に具体的な結果が出ない。役職も習熟論点と連動しない。
- TYPE 3に届かない理由: 解説から次の疑問への橋、概念間リンク、説明生成、現実ケースへの転移、理解に応じた世界変化がない。外発的なXPを外すと固定問題集の反復が残る。

## 10. 「もう1問」を生む力

### 現在成立する理由: 3.5個

1. **ステージ/章クリアまであと少し**: Chapter x/nで部分成立。ただし第8章94問は遠すぎる。
2. **次の仕事が気になる**: ホームの「次の仕事」で部分成立。回答直後には予告がない。
3. **役職を上げたい**: Lv/役職で部分成立。ただし残りXP・変化通知・解放がない。
4. **苦手問題を克服したい**: 誤答一覧と誤答回数順で成立。ただし一度正解で復習対象から消える。
5. **HPを回復したい**: 正解+5により成立するが、これは健全な好奇心より損失回復動機なので0.5相当と評価。

### 成立しない理由

次問の概念的予告、レベルまであと1問、コンボ、解放予告、分岐ストーリー、自己ベスト、昨日比較、定着予定、論点マスター判定、「この場合は？」の問い返しはない。結果画面のCTAは単に「次へ進む」であり、自発理由を言語化しない。

## 16. P0改善項目

### P0-1 非仕訳資料と正答比較を成立させる（難易度M、期待効果: 極大）

1. **現状**: `materials` はE/C/L等にあるが `renderQuestion`/`renderTable` が参照しない。表結果も `renderCorrectJournal` の対象外。
2. **問題**: 情報不足で正答不能な問題と、誤り箇所が分からない問題がある。
3. **ユーザー心理**: 「自分が分からない」ではなく「アプリが壊れている」と判断し、信頼を失う。
4. **改善案**: type別のsemanticな資料表を問題文直下に描画し、結果では全入力セルを本人値/正答/正誤で比較する。模試中のみ結果を保留し、終了後に全問レビューを出す。
5. **変化**: 訂正・総合問題が初めて教材として成立し、誤答が次の学習行動へ変わる。
6. **実装難易度**: M。
7. **期待効果**: Critical障害解消、信頼、理解、有能感、合格力が大幅向上。
8. **優先度**: P0。公開前必須。

### P0-2 HP/勝負回答を学習安全側へ再設計（難易度S〜M、期待効果: 大）

1. **現状**: 誤答でHP -10/-30、正解で+5、0で資金ショート。勝負正解はXP3倍。
2. **問題**: メタ認知測定値を保存・較正せず、誤答を強い損失へ変える。
3. **ユーザー心理**: 初心者が推論を試さず、簡単問題だけ選ぶか離脱する。
4. **改善案**: 確信度は「自信あり/迷った/勘」にして正誤との4象限を返す。HPは廃止、または会社の「未解決伝票」とし、復習で必ず回復・失敗しても進行を遮断しない。
5. **変化**: 間違いを脅威から診断情報へ変え、誤概念とケアレスミスを分けられる。
6. **実装難易度**: S（罰停止）〜M（較正履歴）。
7. **期待効果**: 初心者・不安層の初日/3日維持、学習方略の改善。
8. **優先度**: P0。

## 20. 最終判定

### Q1: 初心者なら30日使い続けたいか

**NO（現状）**。最初の数日は仕訳診断を使いたいが、資料欠落、表の答え合わせ不足、反復、成長の見えなさにより30日継続は選ばない。P0/P1完了後なら条件付きYESになり得る。

### Q2: 「勉強しなければ」から「もう1問やりたい」へ転換できるか
